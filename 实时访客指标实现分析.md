# Plausible Analytics 实时访客指标实现分析

## 1. 概述

Plausible Analytics 的实时访客指标采用了一套精心设计的近实时刷新机制，能够在界面上展示接近实时的在线用户数量。本文将从数据采集、存储、查询聚合到前端刷新的完整流程进行深入分析。

## 3. 页面加载后实时刷新的启动时机

### 3.1 启动时间点

实时刷新的定时器在页面加载的**非常早期**就启动了，具体位置在 `dashboard.tsx`：

```javascript
// dashboard.tsx:1-28
import React, { ReactNode } from 'react'
import { createRoot } from 'react-dom/client'
import 'url-search-params-polyfill'

// ... 其他导入 ...
import * as timer from './dashboard/util/realtime-update-timer'
// ... 其他导入 ...

timer.start()  // ← 模块级代码，在任何组件渲染之前就执行

const container = document.getElementById('stats-react-container')

// ... 后续的 React 渲染逻辑 ...
```

**关键要点**：
1. **执行时机**：`timer.start()` 是模块级代码，在 JavaScript 文件加载并解析时立即执行
2. **早于组件渲染**：定时器启动发生在 React 组件挂载（`root.render(app)`）之前
3. **首次 tick 延迟**：使用 `setInterval`，首次触发在 **30 秒后**，而不是立即

### 3.2 首次数据获取

虽然定时器每 30 秒才触发一次，但 `CurrentVisitors` 组件会在挂载时立即获取数据：

```javascript
// current-visitors.js:32-34
useEffect(() => {
  updateCount()  // 组件挂载时立即执行
}, [dashboardState, updateCount])
```

**完整的初始化流程**：

```
1. 页面加载
    ↓
2. JS 文件解析执行
    ↓
3. timer.start() 启动 (设置 30 秒间隔)
    ↓
4. React 组件树渲染
    ↓
5. CurrentVisitors 组件挂载
    ↓
6. useEffect 触发 → 立即调用 updateCount() → API 请求
    ↓
7. 30 秒后 → 首次 tick 事件 → 再次 API 请求
    ↓
8. 之后每 30 秒循环
```

## 4. 实时图表刷新逻辑：invalidateQueries 与 staleTime 的配合

### 4.1 核心概念澄清

在深入分析之前，需要明确 React Query 中的两个关键概念：

| 概念 | 含义 | 作用 |
|------|------|------|
| **`staleTime`** | 缓存"变旧"的时间 | 数据获取后，在这段时间内被认为是"新鲜"的，不会自动重新获取 |
| **`invalidateQueries`** | 强制标记查询为失效 | 立即触发重新获取，忽略 `staleTime` 设置 |

**关键关系**：
- `staleTime` 是**被动过期**：时间到了才变旧
- `invalidateQueries` 是**主动失效**：立即触发刷新
